## Draft release highlights

0.3.0 completes Stage 6, verification and repair, and brings the following changes since 0.2.0:

- **Run without Docker.** Bundles for Windows x64, macOS arm64 and Linux x64/arm64 include
  PostgreSQL 16, Python, the sidecar, worker and matching plugin. Windows has a tray launcher;
  macOS has a menu-bar app. Docker remains available.
- **Move or back up memory with NMOS Archive.** Export conversations, canon, repairs, links and
  recorded requests from the panel; restore them into a fresh install. Model extractions and
  summaries are included by default, embeddings optionally. Keys and the auth token are excluded.
- **Preview a name repair before applying it.** Joining or splitting names, and undoing those
  actions, shows the effects first. Repairs can find their item by its source quote after a new
  extraction; unmatched repairs remain visible in Needs attention.
- **Keep what an extraction already found.** Extract all history checks for missed secret reveals
  without replacing those turns' existing facts. A fact dropped by another extraction of the same
  generation is listed in Needs attention with Restore; nothing is restored automatically.
- **Recall more of the answer.** Keyword recall, questions about how things started, given-name
  and romanized-name matching, and `packet-v11` excerpts improve how evidence is selected. Excerpts
  and facts use more of a larger memory budget. Query embedding overlaps recall reads and can start
  at sync, reducing lexical-only fallback when the embedder is slow.
- **See background usage and failures.** The panel shows model-reported token usage and distinguishes
  lexical-only recall and reused packets. The dashboard shows the build version and recent job errors.
- **Connect Google Vertex AI with the key file alone.** For fact extraction, **Load key file** takes a
  service-account JSON key, fills the endpoint's project and lists the Gemini chat models Vertex serves;
  pasting the key still works (ADR 0022 amendment 1, #257, merged after the base above).
- **Correct stale and private memory handling.** Fixes cover packet reuse after settings or canon
  changes, conditional canon branches, markup in narrator names, historical facts' knowledge marks,
  and newly extracted facts when the sidecar and database clocks differ.

The final extractor name and the claims about automatic role endings and full/given-name identity
are **pending NMO-24**. `extract-v15` is the default on the base above; Phase 28's v16 work is an
unmerged candidate. Neither its default switch nor its live regression gate is complete in this draft.

## Upgrade notes to carry into the release

Use the [English upgrade guide](../../README.md#upgrade-backup-and-rollback) or
[Korean upgrade guide](../guide.ko.md#업데이트--백업--되돌리기) for the commands and platform paths.

- Back up the database before upgrading Docker. For a bundle, quit NMOS before backing up its
  data and existing configuration; macOS keeps both in Application Support. Restore a pre-upgrade
  backup to roll back. NMOS Archive is for export/restore and does not replace that rollback backup.
- Update the sidecar and plugin together, then reload PocketRisu. Check that the panel reports
  matching builds. Existing Docker `.env` version pins must select the intended release too.
- The base adds migrations **0027 (model usage)** and **0028 (reveal checks and dropped-fact restore)** after 0.2.0's 0026.
  Startup applies migrations. Recheck the final migration range before publishing.
- With extraction configured, the final new extractor generation re-extracts recent turns once
  (`NMOS_EXTRACT_BACKFILL`, default 100) and reads canon again at the provider's cost. Older turns
  keep their existing facts until Extract all history. Do not ask users to run Rebuild memory as
  a routine upgrade step: it discards derived facts and re-extracts the whole chat.
- A milestone carries at most one new extractor generation. Publish the final generation and its
  measured cost once NMO-24 decides it; do not prescribe separate v14, v15 and v16 upgrade passes.
- The default memory budget is 4,000 tokens, previously 2,000. If using the default, leave another
  2,000 tokens of room in the host context. The embedding chunk cap remains 8, so the cap alone
  causes no re-embedding on upgrade; explicitly changing it creates a new embedding projection.
- After extraction finishes, inspect failed jobs, coverage and Needs attention. A repair whose
  item the new generation no longer states remains there for the owner to inspect.

## Known limitations for the release notes

These are a selected user-facing summary of [KNOWN-ISSUES](../KNOWN-ISSUES.md), not new verification:

- Long chats and edits of older messages can exceed the default deadline; memory fails open.
  Mobile latency is not measured (K1–K4).
- Reload the host after installing, updating or disabling the plugin. Use localhost or HTTPS;
  group chats and other host builds do not inherit the recorded host evidence (K5–K7).
- Names and extracted facts can still be wrong. Owner repairs remain necessary; third-person
  persona recall and short Korean keywords with particles remain limited (K8, K32, K40).
- Grown excerpts can contain superseded values (K39). Do not turn individual replay improvements
  into a claim that all live scenarios pass; NMO-24 must supply the release's final evidence.
- Story summaries have no input cap; a large lorebook can add latency, and identity conflicts
  with canon are not flagged automatically (K35–K37).
- iPhone Export everything saved successfully but may trigger a host alert. Export this chat
  was not tapped on the phone; Android export is unverified (K38).
- Vertex's **Load key file** was checked in a real PocketRisu on desktop Chromium only; Safari and iPhone
  are unchecked, and pasting the key remains the fallback there.
- macOS bundles are signed ad hoc and need the documented first-launch allowance. Termux,
  Stage 7 forensic recall and the Stage 8 host bridge are outside this release.

K41 is evidence about the earlier v14 experiment, not a measured result for the final 0.3.0
extractor. Keep that distinction when finalizing limitations. The K42 historical-visibility fix
and K33 budget improvement are already on the base; do not list them as unresolved 0.3.0 defects.
