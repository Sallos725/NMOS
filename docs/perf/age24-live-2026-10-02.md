# AGE-24 live NMOS benchmark after #247

Measured 2026-10-02; reviewed 2026-10-03. **9/9 runs completed; the combined no-regression gate failed.** The real-chat target passed in all three S0main full-history repetitions, but S1, S2, S3 and S4b have regressions against the historical NMOS lane. Do not close AGE-24 or describe the live run as a pass.

This records measurements, not a product-code change or authorization for a new phase. [Machine-readable results](age24-live-2026-10-02/results.json) retain aggregate metrics, failed case IDs and source-result hashes without publishing private conversations.

## Method and scope

- Pinned NMOS commit: `e13dee732d0660a5347a9020bf3de12a5fdc71c9` (#247 merge); the later #248 dashboard change is outside this measurement. Matching plugin SHA-256 is in the JSON.
- Extractor `extract-v15`, `gemma4:31b-cloud`, worker concurrency 2; packet-v11 with keyword anchor, 4,000-token reserve. Direct production-style `qwen3-embedding:8b`, 1,000 ms query timeout, eight chunks.
- S0main and S0s2: existing real-chat samples, opened in an isolated PocketRisu instance. S1: a scripted synthetic 240-turn conversation sent through the real host with rerolls and four checkpoints. S2: first connection to that full synthetic conversation, then extraction of the older history. S3–S4b: synthetic lifecycle scenarios; S3 also checks branch/new-chat behavior.
- Evaluation captures the input delivered to the chat-model stub. Correct-answer groups may be satisfied by the host chat window or injected memory; `Memory` below counts only cases needing memory. This is not generated-answer accuracy.
- Before each scored checkpoint, queued/running worker jobs had to remain absent for 120 seconds. The cloud extractor is real; the response model follows fixed scripted replies.
- Comparison: the existing three-bench NMOS/gemma lane. Several intervening code, configuration and stochastic extraction changes differ; this is **not** an isolated #247 A/B test. S0main has three fresh repetitions; the other scenarios each have one.

## Interpretation

S0main full-history memory cases improve from the historical 6/10 to **8/10, 10/10, 8/10**. Each meets the documented live target of at least 8/10; packet means are 7,227 / 7,071 / 6,694 characters, below 8,000. Default-window memory cases are 8/10, 9/10, 8/10 versus 5/10. This is encouraging real-chat evidence, not evidence that every scenario improved.

S1 at 120 turns improves 22/25 → 23/25 and memory 1/3 → 3/3, while forbidden matches increase 2 → 3. At 240 turns it falls **21/25 → 19/25**, despite memory improving **2/4 → 3/4**, because forbidden matches rise **2 → 6**. S1 at 30/60 turns has no memory-needed cases; those perfect scores do not establish long-term recall quality.

S2 default stays 21/25 with different wins/losses; full history falls **22/25 → 20/25**, forbidden **2 → 5**. S3 falls 6/6 → 5/6, S4b 3/3 → 2/3. S4 improves 3/4 → 4/4; branch/new-chat and S0s2 retain their passes.

## Findings grounded in stored traces

### Current roles survive after their story context ends

S1 and S2 current-residence questions receive a turn-1 `role_toward` fact describing the protagonist as the innkeeper’s guest. In S2, a later negative `located_in` assertion records leaving that room, but the guest role has only one history entry and remains `current`. Those predicates have different version keys. This is an obsolete state served as a current fact, not merely a forbidden substring in a correctly labeled history. A change of location cannot in general end every role; the missing role-end evidence needs targeted investigation.

### Split names separate both retrieval and state histories

S4b stores the edited birthday under a full name while the question uses its given name. Both names resolve to separate entities, with no alias/link. Phase 24 intentionally excludes variants already occupied by another entity. The birthday claim moves from historical rank 5 to current rank 11, outside eight available claim slots. On the same stored candidates, changing only the query to the full name moves it to rank 8 and puts the birthday in the packet. The old edited value is absent.

S2 also resolves full/given names separately. The given-name entity has a later familiar form of address, while the full-name entity keeps an older polite form as its current fact. A role termination under one spelling cannot update another entity’s history. A read-only owner-link diagnostic removes the old current address and recovers the S4b birthday in its fixed-candidate packet. It does not close the old guest role or a positive/negative employment pair with different descriptions. The [proposal](../proposals/AGE24-LIVE-REGRESSIONS.md) records those controls and their side effects.

### Correct retrieval can still omit the answer; current questions can select old passages

S3’s book-title fact is present and extracted before the question, but ranks 24th, outside the 16 fact slots. Vector recall selects the source and a chunk containing the title; excerpt sentence scoring instead chooses a nearby character-name match and omits the title. `memory_cut=0`: this is selection/anchoring, not final token truncation.

In S1/S2, current-location and current-address questions select early excerpts containing old residence or address terms even when the correct current answer is also available. S1’s three newly failed final cases are `c240_02_location`, `c240_03_location`, `c240_05_address`; the early one-off `c240_21_early` recovers.

### Raw forbidden counts are not semantic error counts

`c240_06_address` also matches the old title inside a passage proposing to stop using that title. That match alone does not establish a stale current-state assertion. In S2 it additionally appears in labeled before/first history; independently, the split full-name entity still serves an old current address fact. `3호실` and `갈매기 여관 3호실` count twice in one guest-role sentence. Keep the raw scores for comparability and retain these classifications alongside them; do not silently rescore the gate.

## Diagnostic controls and limits

- S3 and S4b read-only comparisons first reproduced the recorded v11 packet ledger and text with fixed selected candidates and uniquely reconstructed vector spans. Switching only to v10 still missed the answer in each. Turning name variants off also failed. These controls do not cover S1/S2 or establish that v11 has no regressions elsewhere.
- Fixed-candidate/query-name comparisons are diagnostics, not new live runs; their outcomes do not replace the failed original scores.
- Final S1 ledger check: all 480 expected messages through 240 turns, including the selected rerolls, matched exactly once and in story order. This verifies active source content, not every extraction or historical checkpoint state.
- No confidence interval or stable effect size is claimed for single-run scenario differences. Confirmed stale-state examples stand separately from uncertain score deltas.

## Run interruptions and provenance

The harness searches for a raw 40-character reply prefix in rendered text. Host quote formatting caused 37 display-check timeouts; these are not measured extraction latency. Final source integrity passed. A separate quote-normalizing harness candidate was tested but **not applied** to this run.

The local counting proxy stopped at its initial 1,890-call ceiling after S1 turn 231. With owner approval the ceiling became 2,000. Exactly one extraction job failed solely because of that local 429; it was retried with the identical payload/dedupe key and succeeded on the first retry. No successful extraction was discarded or repeated. Prior result files, driver and input hashes remained unchanged; the original driver resumed. The final scoring supervisor continued the same pending execution; it did not restart the scenario.

The proxy logged **1,903 calls: 1,902 successful, one initial CPU-endpoint authentication failure**; reported usage totals **14,767,708 input / 1,445,225 output tokens**. Local blocked attempts at the ceiling were not forwarded and are not cloud calls. S1 final capture completed at 23:51:57 KST on October 2; all result files were assembled at about 23:52.

Private raw chats, requests, traces and DBs remain in the operator’s isolated evaluation environment. This PR includes aggregate counts and synthetic-case explanations only. Exact rerunning requires those private inputs and the pinned host/harness; the JSON hashes identify the measured files but do not make the dataset public.
